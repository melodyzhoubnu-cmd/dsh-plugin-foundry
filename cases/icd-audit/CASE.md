# Case：病案编码质控（dsh-icd-rule-check）

> **结论：通过。** 规则库带条款引用，做不了的检查明确 `skipped`；模型既没有条款原文，也很难忍住不越权下结论。

**一句话**：一份病案首页的编码记录 → 一份带条款引用的差异清单：5 条发现、7 条「查不了所以没查」。
非多模态、离线、确定性输出，规则集和引用都在插件里。

仓库：[PerryLink/dsh-icd-rule-check](https://github.com/PerryLink/dsh-icd-rule-check)（npm `dsh-icd-rule-check@0.2.12`，Apache-2.0）

## 为什么这次绕不过去

不是「本地代码能写」这一类，而是**规则 + 引用 + 不越权**：

1. **12 条规则带出处**：GB/T 14396-2016、国卫办医发〔2016〕24号、医保办发〔2020〕20号，每条都有文件名、文号、条款号和逐字摘录。
2. **条款类型决定严重级**：直接条款才能报 `error`；原则性推论封顶 `warn`；本机构配置封顶 `info`。这一层是产品逻辑，不是正则。
3. **做不了就说做不了**：IC-003 没配「剑号↔星号对照表」，报告直接写 `skipped：无法判断配对是否成立`，不猜。

第 3 条是关键——**模型在这里最容易犯错**：看到 `H28.0*` 没有对应的剑号，一个自信的模型会直接判「星号未配对，错误」。插件会说「没有对照表，不判断」。这是「少报」而不是「多报」，也正是质控场景要的。

## 埋的 5 处

| 规则 | 位置 | 问题 | 级 |
|---|---|---|---|
| IC-001 | 其他诊断 `心梗` | 不是 ICD-10 形式 | error |
| IC-007 | 主要手术 `360600` | 不是 ICD-9-CM-3 形式（缺点号） | error |
| IC-002 | 其他诊断 `E11.900` | 同一编码重复出现 | warn |
| IC-006 | 主要诊断 `I10` | 入院病情代码为 4（「无」）却作主要诊断 | warn |
| IC-008 | 主诉 vs 诊断名 | 没有可识别的字面重叠 | info |

另外 `H28.0*` 是故意放进去的：它没有配对剑号，但插件**不报**，而是在 skipped 里说明没有对照表。

## 边界

- **0 star、新仓库**：今天还在推 commit，有 CI 和 npm 包，但社区验证少。规则集版本 2026.1，规则本身是数据文件，可替换。
- **不查编码目录**：只核形式、重复、成对、字段齐备，不判断某个码在不在你的目录里——这是它自己写明的边界。
- **材料要 JSON/YAML**：Excel 病案首页得先转；对话里可以让 agent 代转。
- **只列差异，不判合规**：报告自带免责声明，最终结论仍由编码员下。
